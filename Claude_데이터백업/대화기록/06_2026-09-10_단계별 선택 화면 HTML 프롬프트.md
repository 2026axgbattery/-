아래는 그대로 복사해서 AI(예: Claude)에게 전달하면 원하시는 단계별(버튼 클릭 진행) HTML을 만들어낼 수 있는 프롬프트입니다. 괄호 안 항목들은 실제 상황에 맞게 채워 넣으시면 됩니다.

```
다음 요구사항에 맞는 단일 HTML 파일(인라인 CSS/JS 포함)을 만들어줘.

[전체 목적]
사용자가 화면에서 버튼을 하나씩 누르면서 단계별로 진행하는 웹 앱(위저드 형식)을 만든다.
모든 단계는 하나의 HTML 파일 안에서 화면 전환(show/hide) 방식으로 구현하고, 
각 단계에서 선택하거나 입력한 데이터는 JS 객체(state)에 누적 저장한다.

[전체 흐름]
1단계: 기초 자료 입력 화면
   - 입력 항목: (예: 작성자명, 작성일자, 프로젝트명, 담당부서 등 필요한 텍스트/날짜/선택 필드)
   - 모든 필수 항목이 입력되어야 "다음" 버튼이 활성화된다.
   - "다음" 버튼을 누르면 2단계(공장 선택) 화면으로 자동 전환된다.

2단계: 공장 선택 화면
   - 버튼 형태로 공장 목록을 나열한다. (예: A공장, B공장, C공장 ... - 실제 목록은 나중에 교체 가능하도록 배열 변수로 분리)
   - 버튼을 누르면 해당 공장이 선택되며, 선택과 동시에 자동으로 3단계(분야 선택)로 전환된다.

3단계: 분야 선택 화면
   - 2단계에서 선택한 공장에 따라 분야 목록이 달라질 수 있도록 구조를 만든다. (공장별 분야 매핑 객체)
   - 버튼 클릭 시 선택 즉시 4단계(공정 선택)로 자동 전환된다.

4단계: 공정 선택 화면
   - 3단계에서 선택한 분야에 따라 공정 목록이 달라지도록 매핑 구조로 만든다.
   - 버튼 클릭 시 선택 즉시 5단계(최종 확인 화면)로 전환된다.

5단계: 최종 확인 화면
   - 지금까지 입력/선택한 모든 데이터(기초자료, 공장, 분야, 공정)를 요약해서 보여준다.
   - "제출" 버튼과 "처음부터 다시" 버튼을 둔다.

[공통 요구사항]
- 화면 상단에 현재 몇 단계인지 보여주는 진행 표시줄(스텝 인디케이터)을 넣는다.
- 각 단계 화면에는 "이전" 버튼을 넣어 이전 선택을 유지한 채 뒤로 돌아갈 수 있게 한다.
- 뒤로 갔다가 다시 선택을 바꾸면, 그 이후 단계에서 저장된 데이터는 초기화되도록 한다.
  (예: 공장을 바꾸면 이미 선택했던 분야/공정 값은 리셋)
- 반응형 디자인(모바일에서도 버튼이 세로로 깔끔하게 나열되도록)
- 디자인은 깔끔하고 현대적인 느낌(카드형 레이아웃, 은은한 그림자, 부드러운 전환 애니메이션)
- 공장/분야/공정 목록은 코드 상단에 JS 배열/객체로 분리해서, 나중에 내용만 바꿔도 쉽게 목록을 교체할 수 있도록 한다.
- 별도 외부 라이브러리 없이 순수 HTML/CSS/JS로 작성한다.

위 요구사항을 반영한 완성된 HTML 코드를 작성해줘.
```

**팁**
- 실제로 사용하실 "공장/분야/공정" 목록과 "기초 자료" 항목(예: 담당자, 날짜 등)을 미리 정리해두시면, 프롬프트의 괄호 부분에 바로 채워 넣어서 훨씬 정확한 결과를 받을 수 있습니다.

### 🤖 Claude · 2026-09-10 09:34

아래처럼 정리해서 프롬프트를 다시 작성했습니다. 정적 HTML 환경이라 실제 서버 라우팅은 불가능하므로, **쿼리스트링(URL 파라미터) + sessionStorage**를 이용해서 "라우팅처럼 보이게" 여러 HTML 파일을 연결하는 구조로 짰습니다. 이대로 AI에게 전달하시면 됩니다.

```
아래 요구사항에 맞춰 여러 개의 HTML 파일을 만들어줘. 
서버 없이 정적 파일만으로 동작해야 하므로, 페이지 이동은 
"URL 쿼리스트링(예: ?category=A&sectionId=3)" + "sessionStorage"를 이용해 
라우팅처럼 동작하게 구현한다. (a 태그 href 이동 또는 location.href 이용)

[전체 파일 구성]
1) index.html            : 메인 페이지 (기초 자료 입력)
2) category.html          : 카테고리별 섹션 목록 페이지 (공용 템플릿, 쿼리값에 따라 내용 변경)
3) detail.html            : 섹션 상세 페이지 (공용 템플릿, 쿼리값에 따라 내용 변경)

[데이터 저장 방식]
- 각 단계에서 입력/선택한 값은 sessionStorage에 누적 저장한다. (key: appState)
- 페이지를 이동해도 이전 단계 데이터가 유지되어야 한다.
- 뒤로가기 등으로 상위 단계 값이 바뀌면, 그 이후 단계 데이터는 초기화한다.

──────────────────────────
[1단계] index.html - 기초 자료 입력 & 카테고리 라우팅
──────────────────────────
- 입력 항목: (예: 작성자명, 작성일자, 프로젝트명 등 필요한 필드 - 실제 항목은 이후 채워 넣을 예정이니 
  변수/폼 구조로 분리해서 나중에 쉽게 바꿀 수 있게 만들어줘)
- 특정 입력값(예: 파일 종류, 구분 값 등 - 실제 어떤 입력값이 카테고리를 결정하는지는 
  categoryMap 같은 JS 객체로 분리)에 따라 이동할 카테고리가 결정된다.
- "다음" 버튼 클릭 시:
  1. 입력값 유효성 검사
  2. sessionStorage에 기초 자료 저장
  3. 입력값에 매핑된 category 값을 쿼리스트링으로 붙여서 category.html로 이동
     예: category.html?category=A

──────────────────────────
[2단계] category.html - 카테고리별 섹션 선택 (동적 라우팅 공용 페이지)
──────────────────────────
- URL의 category 파라미터를 읽어서, 해당 카테고리에 맞는 "섹션 목록"을 렌더링한다.
  (카테고리별 섹션 목록은 sectionMap = { A: [...], B: [...], C: [...] } 같은 JS 객체로 관리)
- 섹션은 버튼/카드 형태로 나열하고, 각 섹션은 고유 ID(key)를 가진다.
- 섹션 버튼 클릭 시:
  1. sessionStorage에 선택한 category, sectionId 저장
  2. detail.html로 이동하면서 쿼리스트링에 category와 sectionId 전달
     예: detail.html?category=A&sectionId=3
- "이전" 버튼 클릭 시 index.html로 돌아가되, 기초 자료 입력값은 유지되어 폼에 다시 채워진다.
- 상단에 현재 어떤 카테고리인지 표시.

──────────────────────────
[3단계] detail.html - 섹션 상세 (동적 라우팅 공용 페이지)
──────────────────────────
- URL의 category, sectionId 파라미터를 읽어서 해당 섹션에 맞는 콘텐츠를 렌더링한다.
- 콘텐츠 데이터는 detailContentMap[category][sectionId] 같은 구조의 JS 객체로 관리하여, 
  동일한 HTML/CSS 템플릿에 내용(제목, 설명, 표, 입력폼 등)만 바뀌어 표시되도록 한다.
- 이 페이지에서도 사용자가 추가 입력/선택을 할 수 있다면, 해당 값도 sessionStorage에 누적 저장한다.
- "이전" 버튼 클릭 시 category.html?category=A 로 돌아가며 이전에 선택했던 섹션 목록 상태 유지.
- (선택 사항) 모든 단계 완료 후 "최종 확인" 페이지(confirm.html)로 이동하여 
  sessionStorage에 쌓인 전체 데이터를 요약해서 보여주고 "제출" 버튼을 배치한다.

──────────────────────────
[공통 요구사항]
──────────────────────────
- 3개(또는 4개) 파일 모두 상단에 진행 단계를 보여주는 스텝 인디케이터를 넣는다.
- 카테고리/섹션/상세 콘텐츠 데이터는 전부 파일 상단에 JS 객체/배열로 분리해서, 
  나중에 실제 데이터로 교체하기 쉽게 만든다. (지금은 예시 더미 데이터로 채워도 됨)
- 반응형 디자인, 카드형 레이아웃, 부드러운 전환 애니메이션 적용.
- 외부 라이브러리 없이 순수 HTML/CSS/JS로 작성.
- 각 파일은 독립적으로 열어도 최소한 오류 없이 동작해야 한다 
  (필요한 파라미터가 없을 경우 index.html로 리다이렉트하는 방어 코드 포함).

위 구조에 맞춰 index.html, category.html, detail.html 
(필요하다면 confirm.html까지) 전체 코드를 작성해줘.
```

**핵심 질문은 이거예요: "페이지 이동"을 어떤 방식으로 만들지예요.**

지금 만들려는 건 서버(백엔드) 없이 그냥 HTML 파일들만 있는 거잖아요? 이런 경우 "라우팅"(페이지 주소가 바뀌면서 내용이 바뀌는 것)을 만드는 방법이 크게 두 가지예요.

### 방법 1: 파일을 여러 개 만들고, 주소에 정보를 붙여서 이동
- 예를 들어 `category.html?category=A` 이런 식으로 주소 뒤에 `?category=A` 를 붙여서 보내요.
- `category.html` 파일은 하나인데, 주소 뒤에 붙은 `A`, `B`, `C` 값을 읽어서 "아, A 카테고리구나" 하고 그에 맞는 내용을 화면에 보여주는 거예요.
- 그래서 category.html 파일 하나로 A든 B든 C든 다 처리 가능해요 (내용만 자바스크립트로 바꿔치기).
- 예전 응답에서 제가 제안한 게 이 방식이에요.

### 방법 2: 그냥 파일 하나에 다 넣고, 화면만 바꿔치기 (제일 처음에 만들어드렸던 방식)
- 주소는 안 바뀌고, 그냥 화면 안에서 "이 부분 숨기고 저 부분 보여주기"로 처리
- 파일 하나로 끝남. 훨씬 간단함.

대신 "동적 라우팅"으로 원하셨던 부분 — 즉 **섹션마다 ID(key)가 있고, 그 ID에 따라 같은 템플릿에 다른 내용이 들어가는 것** — 은 그대로 살리되, URL 대신 **JS 변수(state)로 현재 어떤 카테고리/섹션인지 기억**하고, 그 값에 따라 화면 내용만 바꿔주는 방식으로 처리하면 됩니다.

아래 프롬프트로 정리했습니다. 이대로 AI에게 전달하시면 돼요.

```
다음 요구사항에 맞는 "단일 HTML 파일"(주소창 URL은 절대 바뀌지 않음)을 만들어줘.
페이지 이동처럼 보이지만 실제로는 모두 JS로 화면(section)을 숨기고 보여주는 방식(SPA 느낌)으로 구현한다.

[전체 흐름]

1단계: 기초 자료 입력 화면
   - 입력 항목: (예: 작성자명, 작성일자, 프로젝트명 등 - 실제 항목은 폼 구조로 분리해서 나중에 쉽게 바꿀 수 있게)
   - 특정 입력값(구분/종류 값)에 따라 다음에 보여줄 "카테고리"가 결정된다.
     (이 매핑은 categoryMap 같은 JS 객체로 분리)
   - "다음" 버튼 클릭 시, 입력값을 state 객체에 저장하고 2단계 화면으로 전환.

2단계: 카테고리별 섹션 목록 화면 (공용 템플릿)
   - state에 저장된 category 값에 따라 sectionMap[category] 목록을 화면에 렌더링.
   - 각 섹션은 고유 ID(key)를 가지며, 버튼/카드 형태로 나열.
   - 섹션 버튼 클릭 시:
     1. 클릭한 섹션의 ID(key)를 state에 저장 (state.sectionId = key)
     2. 3단계 화면(상세 페이지)으로 전환하되, 화면은 "같은 템플릿"을 재사용하고 
        내용만 state.sectionId 값에 따라 다르게 렌더링한다.
   - "이전" 버튼 클릭 시 1단계로 돌아가되, 입력했던 값은 폼에 그대로 남아있는다.

3단계: 섹션 상세 화면 (공용 템플릿, key에 따라 내용만 다르게 렌더링)
   - detailContentMap[category][sectionId] 같은 JS 객체에서 
     현재 state.category / state.sectionId 에 해당하는 콘텐츠(제목, 설명, 표, 입력폼 등)를 
     읽어와서 "동일한 레이아웃"에 내용만 갈아끼워 렌더링한다.
   - 이 화면에서도 추가 입력이 있다면 state에 누적 저장.
   - "이전" 버튼 클릭 시 2단계(해당 카테고리의 섹션 목록)로 돌아간다.

(선택) 4단계: 최종 확인 화면
   - state에 누적된 전체 데이터(기초자료 + category + sectionId + 상세 입력값)를 요약해서 보여준다.
   - "제출" 버튼, "처음으로" 버튼 배치.

[공통 요구사항]
- 화면 전환은 전부 JS로 특정 <div> 보이기/숨기기 방식으로 처리 (주소창 URL 변경 없음, location.href/redirect 사용 금지).
- 전체 데이터는 하나의 JS 객체(state)에 누적 저장하고, 각 화면 렌더링 함수는 이 state를 참조해서 그린다.
- 상위 단계 값이 바뀌면(예: 카테고리를 다시 선택), 그 이후 단계에 저장된 데이터는 초기화한다.
- 화면 상단에 현재 몇 단계인지 보여주는 스텝 인디케이터를 넣는다.
- 카테고리 목록, 섹션 목록, 섹션별 상세 콘텐츠는 전부 파일 상단에 
  JS 객체/배열로 분리해서 나중에 데이터만 바꿔도 쉽게 교체 가능하게 한다. (지금은 예시 더미 데이터로 채워도 됨)
- 반응형 디자인, 카드형 레이아웃, 부드러운 전환 애니메이션 적용.
- 외부 라이브러리 없이 순수 HTML/CSS/JS로 작성.
- 뒤로가기/새로고침 시 데이터가 사라지는 것은 괜찮음 (URL을 안 바꾸는 대신 감수하는 부분).

위 구조에 맞춰 완성된 하나의 HTML 파일 전체 코드를 작성해줘.
```
